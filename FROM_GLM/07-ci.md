## Назначение

Этот документ описывает, как устроен CI/CD Tensa. Цель: чтобы
GLM 5.3 понимал, что проверяется автоматически, и как подготовить
код, чтобы CI проходил.

---

## Принципы

### 1. CI — обязателен

Без прохождения CI — нет merge. CI — это «ворота» качества.

### 2. CI — быстрый

CI должен проходить за минуты, не часы. Кэширование — обязательно.

### 3. CI — надёжный

CI должен быть детерминированным. Флаки — исправлять.

### 4. CI — информативный

Если CI упал — понятно, что именно и почему.

### 5. CI — автоматизированный

Никаких ручных шагов. Всё автоматически.

## Что проверяет CI

### 1. Форматирование

```bash
cargo fmt --all -- --check
```

**Что проверяет:** код соответствует `rustfmt`.

**Если упал:** запустить `cargo fmt --all`.

### 2. Линтинг

```bash
cargo clippy --workspace --all-targets --all-features -- -D warnings
```

**Что проверяет:** код без warnings Clippy.

**Если упал:** исправить warnings.

### 3. Сборка

```bash
cargo build --workspace --release
```

**Что проверяет:** код компилируется.

**Если упал:** исправить ошибки компиляции.

### 4. Тесты

```bash
cargo test --workspace --all-features
```

**Что проверяет:** все тесты проходят.

**Если упал:** исправить тесты или код.

### 5. Doc-tests

```bash
cargo test --workspace --doc
```

**Что проверяет:** примеры в документации компилируются и работают.

**Если упал:** исправить примеры.

### 6. Покрытие

```bash
cargo llvm-cov --workspace --fail-under-lines 60
```

**Что проверяет:** покрытие тестами ≥ 60% (для критичных — ≥ 80%).

**Если упал:** добавить тесты.

### 7. Аудит зависимостей

```bash
cargo audit
```

**Что проверяет:** нет уязвимостей в зависимостях.

**Если упал:** обновить зависимости или сообщить Архитектору.

### 8. Кросс-компиляция

```bash
cargo build --release --target aarch64-linux-android
cargo build --release --target aarch64-apple-ios
```

**Что проверяет:** код собирается под Android и iOS (точки входа).

**Если упал:** исправить кросс-компиляцию.

## Структура CI

### `.github/workflows/ci.yml`

```yaml
name: CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]

env:
  CARGO_TERM_COLOR: always
  RUST_BACKTRACE: 1

jobs:
  fmt:
    name: Format
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: rustfmt
      - run: cargo fmt --all -- --check

  clippy:
    name: Clippy
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: clippy
      - uses: Swatinem/rust-cache@v2
      - run: cargo clippy --workspace --all-targets --all-features -- -D warnings

  test:
    name: Test (${{ matrix.os }})
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - run: cargo test --workspace --all-features

  coverage:
    name: Coverage
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: llvm-tools-preview
      - uses: Swatinem/rust-cache@v2
      - uses: taiki-e/install-action@cargo-llvm-cov
      - run: cargo llvm-cov --workspace --all-features --fail-under-lines 60

  audit:
    name: Audit
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - uses: taiki-e/install-action@cargo-audit
      - run: cargo audit

  android:
    name: Android
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          targets: aarch64-linux-android,armv7-linux-androideabi
      - uses: Swatinem/rust-cache@v2
      - uses: nttld/setup-ndk@v1
        with:
          ndk-version: r26b
      - run: cargo build --release --target aarch64-linux-android

  ios:
    name: iOS
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          targets: aarch64-apple-ios,x86_64-apple-ios-sim
      - uses: Swatinem/rust-cache@v2
      - run: cargo build --release --target aarch64-apple-ios

  macos:
    name: macOS
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          targets: x86_64-apple-darwin,aarch64-apple-darwin
      - uses: Swatinem/rust-cache@v2
      - run: cargo build --release --target aarch64-apple-darwin
```

## Кэширование

### Cargo registry

```yaml
- uses: Swatinem/rust-cache@v2
```

Кэширует:
- `~/.cargo/registry`
- `~/.cargo/git`
- `target/`

**Экономия:** минуты на каждой сборке.

### NDK

```yaml
- uses: actions/cache@v4
  with:
    path: ~/.android-ndk
    key: ndk-r26b
```

### Xcode

Xcode предустановлен на macOS runners.

## Релизы

### `.github/workflows/release.yml`

```yaml
name: Release

on:
  push:
    tags: ['v*']

jobs:
  build:
    name: Build (${{ matrix.target }})
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        include:
          - os: windows-latest
            target: x86_64-pc-windows-msvc
            artifact: tensa-windows-x86_64
          - os: ubuntu-latest
            target: x86_64-unknown-linux-gnu
            artifact: tensa-linux-x86_64
          - os: macos-latest
            target: aarch64-apple-darwin
            artifact: tensa-macos-aarch64
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          targets: ${{ matrix.target }}
      - uses: Swatinem/rust-cache@v2
      - run: cargo build --release --target ${{ matrix.target }}
      - uses: actions/upload-artifact@v4
        with:
          name: ${{ matrix.artifact }}
          path: target/${{ matrix.target }}/release/tensa*

  release:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/download-artifact@v4
      - uses: softprops/action-gh-release@v1
        with:
          files: |
            tensa-windows-x86_64/*
            tensa-linux-x86_64/*
            tensa-macos-aarch64/*
```

## Pre-commit hook

### `.git/hooks/pre-commit`

```bash
#!/bin/bash
set -e

echo "Running pre-commit checks..."

cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features

echo "All checks passed!"
```

Сделать исполняемым:
```bash
chmod +x .git/hooks/pre-commit
```

## Что делать, если CI упал

### 1. Прочитать лог

Открыть Actions → выбрать job → прочитать лог.

### 2. Локально воспроизвести

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
```

### 3. Исправить

Исправить ошибки локально.

### 4. Проверить

Все команды должны пройти.

### 5. Push

```bash
git push
```

### 6. Если не получается

- Спросить Архитектора.
- Не игнорировать CI.
- Не «обходить» CI.

---

## Что НЕ делать с CI

### 1. Не игнорировать

**Плохо:** «CI упал, но я знаю, что код работает».

**Хорошо:** исправить CI.

### 2. Не отключать

**Плохо:** закомментировать job в CI.

**Хорошо:** исправить причину.

### 3. Не «обходить»

**Плохо:** `#[allow(clippy::all)]`.

**Хорошо:** исправить код.

### 4. Не пушить сломанное

**Плохо:** push, зная, что CI упадёт.

**Хорошо:** проверить локально.

### 5. Не коммитить секреты

**Плохо:** `api_key = "sk-or-..."`.

**Хорошо:** `api_key = "${OPENROUTER_API_KEY}"`.

## Секреты в CI

### GitHub Secrets

```
Settings → Secrets and variables → Actions → New repository secret
```

**Что хранить:**
- `OPENROUTER_API_KEY` — для тестов облачной LLM.
- `TELEGRAM_BOT_TOKEN` — для тестов Telegram.
- `CODECOV_TOKEN` — для покрытия.
- `CARGO_REGISTRY_TOKEN` — для публикации.

### Использование

```yaml
- run: cargo test
  env:
    OPENROUTER_API_KEY: ${{ secrets.OPENROUTER_API_KEY }}
```

## Частые ошибки

### 1. Забыл `cargo fmt`

**Плохо:** push без `cargo fmt`.

**Хорошо:** pre-commit hook.

### 2. Игнорирование Clippy

**Плохо:** `#[allow(clippy::all)]`.

**Хорошо:** исправить warnings.

### 3. Тесты без `--all-features`

**Плохо:** `cargo test`.

**Хорошо:** `cargo test --all-features`.

### 4. Отсутствие кэша

**Плохо:** CI собирает всё с нуля.

**Хорошо:** `Swatinem/rust-cache@v2`.

### 5. Секреты в открытом виде

**Плохо:** `api_key = "sk-or-..."` в коде.

**Хорошо:** GitHub Secrets.

### 6. Долгий CI

**Плохо:** CI идёт 30 минут.

**Хорошо:** кэш + параллельность.

### 7. Флаки

**Плохо:** тест иногда проходит, иногда нет.

**Хорошо:** детерминированный тест.
