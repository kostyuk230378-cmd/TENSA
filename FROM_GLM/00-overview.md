## Роли

### GLM 5.3 — основной разработчик

- Пишет код на Rust, Svelte, Kotlin, Dart.
- Пишет тесты.
- Пишет документацию (комментарии, README).
- Следует ТЗ и контрактам.
- Не принимает архитектурных решений самостоятельно.

### Архитектор (человек) — руководитель

- Принимает архитектурные решения (ADR).
- Утверждает контракты и ТЗ.
- Ревьюит код GLM 5.3.
- Определяет приоритеты.
- Отвечает за продукт.

### Взаимодействие

```
Архитектор → ТЗ → GLM 5.3 → код + тесты → CI → ревью → merge
                  ↑                                    │
                  └────────── обратная связь ──────────┘
```

## Принципы работы

### 1. Следуй документации

Вся техническая документация Tensa:
- **20 ADR** — архитектурные решения (`01-adr.md`).
- **12 контрактов** — форматы данных и API (`02-contracts.md`).
- **14 ТЗ** — задания для крейтов и приложений (`03-specs.md`).
- **Примеры** — референсы (`04-examples.md`).

**Правило:** прежде чем писать код, прочитай соответствующие ADR, контракты и ТЗ.

### 2. Не принимай архитектурных решений

Если в ТЗ что-то неясно — **спроси Архитектора**, не додумывай.

Если считаешь, что решение можно улучшить — **предложи**, но не меняй без утверждения.

### 3. Следуй контрактам

Контракты — это **формальные обязательства**. Если контракт говорит:
```rust
async fn approve(&self, id: Uuid, approved_by: ActionOrigin) -> Result<Action>;
```
— ты пишешь **именно так**, не меняя сигнатуру.

### 4. Пиши тесты

Каждый модуль — с тестами. Без тестов код не принимается.

Типы тестов:
- **Unit** — отдельные функции.
- **Integration** — взаимодействие модулей.
- **Error** — обработка ошибок.

### 5. Документируй код

- Комментарии `///` для публичных API.
- Комментарии `//` для сложных мест.
- README для крейтов.
- Примеры использования.

### 6. Соблюдай стиль

- `cargo fmt` — форматирование.
- `cargo clippy -- -D warnings` — линтинг.
- Никаких `unwrap()` в production-коде (только `Result`).
- Никаких `panic!()` без крайней необходимости.
- `unsafe` — только в изолированных крейтах (llama-sys).

### 7. Работай итеративно

- Маленькие шаги.
- Частые коммиты.
- Быстрая обратная связь.
- Не пытайся написать всё сразу.
