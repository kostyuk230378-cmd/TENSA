# Руководство: Установка Tensa в корпоративной сети

**Версия:** 0.1.0
**Дата:** 2026-10-06
**Статус:** Утверждено
**Тип:** Пользовательское руководство
**Связано с:** ADR-002, ADR-007

---

## Назначение

Это руководство описывает, как установить и настроить Tensa в
**корпоративной сети** с учётом:
- Прав администратора.
- Прокси-серверов.
- Firewall.
- Корпоративных политик.
- Безопасности.

**Важно:** Tensa — персональный секретарь для одного человека. Это
руководство описывает установку **на рабочем месте** в корпоративной
среде.

---

## Что нужно

### Права

- **Локальный администратор** на рабочем ПК.
- **Разрешение** от IT-отдела (рекомендуется).
- **Доступ** к интернету (или прокси).

### Компоненты

- **Tensa** (open-source).
- **Tailscale** (для связи).
- **Модели** (Gemma 4 E2B, multilingual-e5-small, Whisper).
- **OpenRouter API key** (для облачной LLM).

### Требования к ПК

- **RAM:** 8+ ГБ (16+ ГБ рекомендуется).
- **Диск:** 20+ ГБ свободно.
- **CPU:** 4+ ядра.
- **ОС:** Windows 10/11, Linux.

---

## Часть 1: Согласование с IT-отделом

### Шаг 1: Подготовить обоснование

**Что включить:**

1. **Что такое Tensa** — персональный ИИ-секретарь.
2. **Зачем нужен** — автоматизация рутины.
3. **Что делает** — поиск документов, почта, календарь.
4. **Что НЕ делает** — не передаёт данные в облако.
5. **Безопасность** — локальные модели, Tailscale.
6. **Лицензия** — open-source (MIT/Apache).

### Шаг 2: Указать требования

**Что нужно:**

1. **Установка** — локально на ПК.
2. **Tailscale** — для связи с телефоном.
3. **Порты** — 50051 (gRPC), 8765 (HTTP).
4. **Интернет** — для OpenRouter (опционально).
5. **Диск** — 20+ ГБ.
6. **RAM** — 8+ ГБ.

### Шаг 3: Ответить на вопросы IT

**Типичные вопросы:**

- **«Какие данные передаются?»** — Только метаданные OpenRouter (если используется). Документы — локально.
- **«Какие порты открываются?»** — 50051, 8765 (только внутри Tailscale).
- **«Какие внешние сервисы?»** — OpenRouter (опционально), Tailscale (обязательно).
- **«Можно ли без интернета?»** — Да, локальные модели работают офлайн.
- **«Как обновляется?»** — Вручную или автоматически (v0.3+).
- **«Как удаляется?»** — Стандартное удаление + удаление `~/.tensa/`.

## Часть 2: Установка за прокси

### Шаг 1: Настроить прокси для Cargo

**Что делать:**

1. Откройте `~/.cargo/config.toml` (или создайте).
2. Добавьте:

```toml
[http]
proxy = "http://proxy.company.com:8080"

[https]
proxy = "http://proxy.company.com:8080"
```

3. Сохраните.

### Шаг 2: Настроить прокси для Git

**Что делать:**

```bash
git config --global http.proxy http://proxy.company.com:8080
git config --global https.proxy http://proxy.company.com:8080
```

### Шаг 3: Настроить прокси для Rust

**Что делать:**

```bash
export HTTP_PROXY=http://proxy.company.com:8080
export HTTPS_PROXY=http://proxy.company.com:8080
```

**Windows (PowerShell):**
```powershell
$env:HTTP_PROXY="http://proxy.company.com:8080"
$env:HTTPS_PROXY="http://proxy.company.com:8080"
```

### Шаг 4: Настроить прокси для Tensa

**Что делать:**

1. Откройте `~/.tensa/config.toml`.
2. Добавьте:

```toml
[network]
http_proxy = "http://proxy.company.com:8080"
https_proxy = "http://proxy.company.com:8080"
no_proxy = "localhost,127.0.0.1,100.64.0.0/10"
```

**Важно:** `no_proxy` — чтобы Tailscale и локальные адреса не шли
через прокси.

## Часть 3: Установка за firewall

### Шаг 1: Открыть порты (если нужно)

**Что открыть:**
- **50051** (gRPC) — для связи с телефоном.
- **8765** (HTTP) — для PWA.

**Важно:** порты открываются **только внутри Tailscale**. Не
наружу.

**Windows (PowerShell от админа):**
```powershell
New-NetFirewallRule -DisplayName "Tensa gRPC" -Direction Inbound -LocalPort 50051 -Protocol TCP -Action Allow -Profile Private
New-NetFirewallRule -DisplayName "Tensa HTTP" -Direction Inbound -LocalPort 8765 -Protocol TCP -Action Allow -Profile Private
```

**Linux (ufw):**
```bash
sudo ufw allow from 100.64.0.0/10 to any port 50051
sudo ufw allow from 100.64.0.0/10 to any port 8765
```

### Шаг 2: Настроить Tailscale

**Что делать:**

1. Установите Tailscale.
2. Войдите в аккаунт.
3. Проверьте, что устройство в сети.

**Важно:** Tailscale использует порт 41641 (UDP). Убедитесь, что
он не заблокирован.

### Шаг 3: Проверить соединение

**Что делать:**

1. Откройте браузер.
2. Введите `http://localhost:8765/health`.
3. Если видите `{"healthy": true}` — работает.

## Часть 4: Настройка почты

### Шаг 1: Получить настройки IMAP/SMTP

**Что нужно от IT:**

- **IMAP host** (например, `imap.company.com`).
- **IMAP port** (993 или 143).
- **SMTP host** (например, `smtp.company.com`).
- **SMTP port** (587 или 465).
- **Логин** (ваш email).
- **Пароль** (или OAuth2).

### Шаг 2: Настроить в Tensa

**Что делать:**

1. Откройте Tensa.
2. Перейдите в **Настройки → Почта**.
3. Нажмите **«Добавить ящик»**.
4. Введите данные.
5. Нажмите **«Проверить соединение»**.
6. Если всё ок — нажмите **«Сохранить»**.

### Шаг 3: Настроить OAuth2 (если требуется)

**Что делать:**

1. В настройках почты выберите **«OAuth2»**.
2. Выберите провайдера (Google, Microsoft, custom).
3. Введите Client ID и Client Secret (получите у IT).
4. Нажмите **«Авторизоваться»**.
5. Войдите в аккаунт.
6. Разрешите доступ.

## Часть 6: Настройка OpenRouter (опционально)

### Шаг 1: Получить API key

**Что делать:**

1. Откройте **https://openrouter.ai**.
2. Зарегистрируйтесь.
3. Пополните баланс.
4. Создайте API key.
5. Скопируйте.

### Шаг 2: Настроить в Tensa

**Что делать:**

1. Откройте Tensa.
2. Перейдите в **Настройки → ИИ**.
3. Введите **OpenRouter API key**.
4. Настройте лимиты:
   - **Дневной лимит токенов:** 100 000.
   - **Месячный лимит USD:** $10.
5. Нажмите **«Сохранить»**.

**Важно:** если корпоративная политика запрещает внешние API —
отключите OpenRouter. Tensa будет работать только на локальной
модели.

## Часть 7: Безопасность в корпоративной среде

### 1. Локальные модели

- Все модели работают локально.
- Документы не уходят в облако.
- LLM не передаёт данные.

### 2. Tailscale

- Шифрование WireGuard.
- P2P-соединение.
- Только ваши устройства.

### 3. ApprovalStore

- Все действия через одобрение.
- Вы контролируете, что делает Tensa.
- Аудит всех действий.

### 4. Аудит

- Все действия логируются.
- Логи в `~/.tensa/logs/`.
- Можно экспортировать.

### 5. Шифрование at rest (v0.2+)

- Опционально.
- Для конфиденциальных данных.

### 6. Remote wipe (v0.2+)

- Опционально.
- Для потери устройства.

## Часть 8: Корпоративные политики

### 1. Что может быть запрещено

- **Внешние API** (OpenRouter) — используйте локальные модели.
- **Tailscale** — используйте корпоративный VPN.
- **Порты** — согласуйте с IT.
- **Установка ПО** — получите разрешение.

### 2. Что делать, если запрещено

**Если запрещён OpenRouter:**
- Отключите в настройках.
- Используйте локальную модель.
- Качество будет ниже, но приватность — выше.

**Если запрещён Tailscale:**
- Используйте корпоративный VPN.
- Или откажитесь от синхронизации.
- Tensa будет работать локально.

**Если запрещены порты:**
- Согласуйте с IT.
- Или используйте только локальный режим.

### 3. Что делать, если запрещена установка

- Обсудите с IT.
- Предложите open-source решение.
- Предложите аудит кода.

## Часть 9: Troubleshooting

### Tensa не устанавливается

**Проверьте:**
1. Права администратора.
2. Прокси.
3. Антивирус.

**Решение:**
- Запустите от админа.
- Настройте прокси.
- Добавьте в исключения.

### Модели не загружаются

**Проверьте:**
1. Интернет.
2. Прокси.
3. Диск.

**Решение:**
- Настройте прокси.
- Освободите место.
- Скачайте вручную.

### Почта не подключается

**Проверьте:**
1. IMAP/SMTP настройки.
2. Пароль.
3. Firewall.

**Решение:**
- Проверьте настройки у IT.
- Проверьте firewall.
- Используйте OAuth2.

### OpenRouter не работает

**Проверьте:**
1. API key.
2. Баланс.
3. Прокси.

**Решение:**
- Проверьте ключ.
- Пополните баланс.
- Настройте прокси.

### Firewall блокирует

**Проверьте:**
1. Порты 50051, 8765.
2. Tailscale (41641 UDP).

**Решение:**
- Откройте порты.
- Согласуйте с IT.

### Антивирус блокирует

**Проверьте:**
1. Логи антивируса.
2. Карантин.

**Решение:**
- Добавьте Tensa в исключения.
- Согласуйте с IT.

## Часть 10: Удаление Tensa

### Шаг 1: Удалить приложение

**Windows:**
- Параметры → Приложения → Tensa → Удалить.

**Linux:**
```bash
sudo apt remove tensa
```

### Шаг 2: Удалить данные

**Windows:**
- Удалите `%USERPROFILE%\.tensa\`.

**Linux:**
```bash
rm -rf ~/.tensa/
```

### Шаг 3: Удалить Tailscale (опционально)

**Windows:**
- Параметры → Приложения → Tailscale → Удалить.

**Linux:**
```bash
sudo apt remove tailscale
```

### Шаг 4: Удалить из Tailscale

1. Откройте **https://login.tailscale.com/admin/machines**.
2. Найдите устройство.
3. Нажмите **«Remove»**.
