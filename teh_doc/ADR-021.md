# ADR-021: Иерархическая память (Letta-style) на Rust

## Статус
Принято

## Контекст

Tensa — персональный ИИ-секретарь. Ему нужна память, которая:
- Помнит владельца (имя, предпочтения, язык).
- Помнит персону секретаря (как его называть, роль).
- Помнит историю разговоров.
- Помнит документы (долговременное хранилище).
- Может обновляться агентом (LLM).

Текущая архитектура (ADR-004, ADR-005) покрывает:
- Векторный поиск по документам (Lance).
- Эмбеддинги (fastembed-rs).

Но не покрывает:
- Персону агента (как называть секретаря).
- Информацию о владельце (имя, предпочтения).
- Историю разговоров (recall).
- Иерархию памяти (core / recall / archival).

Существующие решения:
- Mem0 — слой памяти, но Python, нет core memory.
- Letta (MemGPT) — иерархическая память, но Python/TypeScript.
- LangGraph / CrewAI — избыточно, Python, не для одного агента.

Ключевое ограничение: код пишет AI-ассистент (GLM 5.3). Нужна
чистая Rust-реализация, без Python-зависимостей.

Рассмотренные альтернативы:
- Mem0 — Python, нет core memory.
- Letta (MemGPT) — Python/TypeScript, тяжёлый.
- LangGraph / CrewAI — избыточно.
- Своя реализация на Rust — выбран.

## Решение

Выбрана своя реализация иерархической памяти на Rust,
вдохновлённая моделью Letta (MemGPT).

### Четыре уровня памяти

**1. Core memory (SQLite)**
- Всегда в контексте LLM.
- Структурированные блоки:
  - persona — персона секретаря (как называть, роль).
  - human — информация о владельце (имя, предпочтения, язык).
  - tasks — текущие задачи.
  - preferences — предпочтения владельца.
- Редактируется агентом через tool calls:
  - core_memory_replace — заменить блок.
  - core_memory_append — добавить в блок.
- Хранится в SQLite (~/.tensa/memory.db).
- Размер ограничен (например, 2000 токенов).

**2. Recall memory (SQLite)**
- Полная история разговоров.
- Поиск по истории (FTS5).
- Не всегда в контексте — извлекается по запросу.
- Хранится в SQLite (~/.tensa/memory.db).
- Агент может искать через recall_memory_search.

**3. Archival memory (Lance)**
- Долговременное хранилище (документы, факты).
- Векторный поиск (Lance, ADR-004).
- Не всегда в контексте — извлекается по запросу.
- Агент может искать через archival_memory_search.
- Агент может добавлять через archival_memory_insert.

**4. Message buffer (в памяти)**
- Скользящее окно последних сообщений.
- Не хранится на диске.
- Используется для контекста LLM.

### Схема

```
┌─────────────────────────────────────────────────────┐
│  LLM (Gemma 4 E2B / 26B A4B)                        │
│  ┌───────────────────────────────────────────────┐  │
│  │  Контекст:                                    │  │
│  │  ├── System prompt                            │  │
│  │  ├── Core memory (persona, human, tasks)      │  │
│  │  ├── Message buffer (последние сообщения)     │  │
│  │  └── Retrieved memories (recall + archival)   │  │
│  └───────────────────────────────────────────────┘  │
└──────────────────┬──────────────────────────────────┘
                   │
                   │ Tool calls
                   ▼
┌─────────────────────────────────────────────────────┐
│  Memory Manager (Rust)                              │
│  ├── CoreMemory (SQLite)                            │
│  │   ├── persona                                    │
│  │   ├── human                                      │
│  │   ├── tasks                                      │
│  │   └── preferences                                │
│  ├── RecallMemory (SQLite + FTS5)                   │
│  │   └── история разговоров                         │
│  └── ArchivalMemory (Lance)                         │
│      └── документы, факты                           │
└─────────────────────────────────────────────────────┘
```

### Tool calls для памяти

**Core memory:**
- core_memory_replace(block: string, value: string) — заменить блок.
- core_memory_append(block: string, value: string) — добавить в блок.

**Recall memory:**
- recall_memory_search(query: string, limit: number) — поиск по истории.

**Archival memory:**
- archival_memory_search(query: string, limit: number) — поиск по архиву.
- archival_memory_insert(content: string, tags: [string]) — добавить в архив.

### Файл памяти при первом запуске

При первом запуске Tensa создаёт core memory blocks:

persona:
```
Я — Tensa, персональный ИИ-секретарь. Моя задача — помогать
владельцу управлять документами, почтой, календарём, Telegram и
приложениями. Я работаю на русском и английском языках. Я не
выполняю действия без одобрения владельца. Я уважаю приватность и
не передаю данные третьим лицам.
```

human:
```
Владельца зовут {owner_name}. Он предпочитает обращение
«{owner_title}». Его язык: {language}. Часовой пояс: {timezone}.
```

tasks:
```
Активные задачи: {active_tasks}
```

preferences:
```
Владелец предпочитает: {preferences}
```

### Что это даёт

- Персона — секретарь знает, как его называть.
- Владелец — секретарь знает, как обращаться.
- История — секретарь помнит разговоры.
- Архив — секретарь помнит документы.
- Обновление — агент сам редактирует память.

### Что это требует

- SQLite для core и recall.
- Lance для archival (уже есть).
- Memory Manager на Rust.
- Tool calls в LLM.
- Ограничение размера core memory.

## Последствия

**Положительные:**
- Чистый Rust — нет Python-зависимостей.
- Персона секретаря — как называть.
- Информация о владельце — имя, предпочтения.
- История разговоров — recall.
- Архив документов — archival.
- Агент сам управляет памятью.
- Иерархия — core / recall / archival.

**Отрицательные:**
- Нужно реализовать Memory Manager.
- Нужно реализовать tool calls.
- Нужно ограничивать размер core memory.
- SQLite + Lance — два хранилища.
- Сложнее, чем Mem0.

**Отложено / точки входа:**
- Sleep-time compute (как в Letta) — v0.2+.
- Автоматическая суммаризация recall — v0.2+.
- Иерархия archival (теги, категории) — v0.2+.
- Синхронизация памяти между узлами — v0.2+ (через gRPC).
