# tensa-router

Маршрутизация запросов к LLM и выбор узла инференса (ТЗ tensa-router;
ADR-001, ADR-002, ADR-003, ADR-012, ADR-013).

## Назначение

- выбор модели: локальная (Gemma 4 E2B, по умолчанию) / облачная
  (Gemma 4 26B A4B, free → paid);
- приоритет запроса: Low/Normal → локальная, High → облако;
- выбор узла: локальный heavy → локально; удалённый heavy → gRPC
  (`QueryService`); иначе — облако; если ничего — degraded (только поиск);
- авто-fallback: бесплатная модель (таймаут 30 с, 2 попытки) → платная →
  локальная → degraded;
- бюджет OpenRouter: 100 000 токенов/день, $10/мес, предупреждение на 80 %,
  блокировка на 100 % (файл `<root>/router_budget.json`);
- health и статус бюджета для UI.

## Точки внедрения

`LocalBackend` (llama.cpp), `CloudBackend` (OpenRouter HTTP), `RemoteBackend`
(gRPC к heavy-узлу). В комплекте — детерминированные заглушки
(`StubLocalBackend`, `StubCloudBackend`, `StubRemoteBackend`) для тестов и CI.

## Статус

- облачный клиент — реальный (`reqwest`, ключ `OPENROUTER_API_KEY`,
  HTTPS/rustls);
- удалённый инференс — реальный gRPC-клиент по Контракту 8;
- стриминг: контракт потока сохранён, поштучная выдача — с нативным слоем
  (TASK-ENV-001);
- USD-стоимость облака подключится с прайс-листом; дневной лимит токенов
  учитывается уже сейчас.
