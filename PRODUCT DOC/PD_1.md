## Что такое Tensa

**Tensa** — персональный ИИ-секретарь. Это программа, которая
помогает одному человеку управлять информацией, документами,
почтой, календарём и коммуникациями.

Tensa — не «чат-бот» и не «ассистент общего назначения». Это
**специализированный секретарь**, который:
- Знает ваши документы.
- Знает ваши контакты.
- Знает ваш календарь.
- Работает с вашей почтой.
- Отвечает на ваши команды.
- Защищает ваши данные.

## Какую проблему решает

### Проблема 1: Информация разбросана

Документы — в папках, почта — в ящике, заметки — в блокноте,
контакты — в телефоне, календарь — в другом приложении.

**Решение Tensa:** единый поиск по всем источникам. Один запрос —
все результаты.

### Проблема 2: Рутина съедает время

«Найди смету за апрель», «Отправь Ивану письмо», «Назначь встречу
на завтра» — это занимает минуты, но повторяется каждый день.

**Решение Tensa:** команда голосом или текстом. Секретарь делает
всё сам.

### Проблема 3: Приватность под угрозой

Облачные ассистенты (Siri, Google Assistant, Alexa) отправляют
данные на серверы. Ваши документы, письма, контакты — не ваши.

**Решение Tensa:** локальные модели, локальное хранилище, Tailscale
для связи. Данные не уходят в облако.

### Проблема 4: Привязка к экосистеме

Apple-пользователи — в Apple, Google-пользователи — в Google.
Переход между экосистемами — боль.

**Решение Tensa:** кроссплатформенность. Windows, Linux, Android.
macOS, iOS — после MVP.

### Проблема 5: Нет контроля над действиями

Облачные ассистенты делают что хотят. Отправили письмо — не
спросили. Создали событие — не спросили.

**Решение Tensa:** ApprovalStore. Все действия — через одобрение.
Вы контролируете, что делает секретарь.

## Ключевые особенности

### 1. Локальный и облачный ИИ

- **Локальная модель** (Gemma 4 E2B) — для офлайн-работы и
  приватности.
- **Облачная модель** (Gemma 4 26B A4B) — для сложных задач.
- **Автоматический fallback:** если облако недоступно — локальная.
- **Экономия:** бесплатная облачная модель → платная → локальная.

### 2. Единый поиск по документам

- **PDF, DOCX, XLSX, PPTX, TXT, MD.**
- **Семантический поиск** — по смыслу, не по ключевым словам.
- **Гибридный поиск** — семантика + ключевые слова.
- **OCR** — для сканированных документов.
- **Работа офлайн** — индекс локальный.

### 3. Работа с почтой

- **IMAP/SMTP** — напрямую, без шлюза.
- **Несколько ящиков** — личный, рабочий.
- **Поиск по письмам** — семантический.
- **Отправка** — через ApprovalStore.

### 4. Календарь

- **CalDAV** — стандартный протокол.
- **Чтение** — свободно.
- **Создание** — через ApprovalStore.
- **Проверка конфликтов** — автоматически.

### 5. Telegram-бот

- **Приём команд** от владельца.
- **Отправка уведомлений.**
- **Интерактивные кнопки** одобрения.
- **Работает на телефоне** без ПК.

### 6. Запуск приложений

- **Открытие файлов** ассоциированными приложениями.
- **Запуск приложений** по имени.
- **Белый список** — только разрешённые.
- **Аудит** — все запуски логируются.

### 7. Многоплатформенность

- **Windows** — Tauri + Svelte.
- **Linux** — Tauri + Svelte.
- **Android** — Flutter + Kotlin.
- **macOS** — после MVP.
- **iOS** — после MVP (PWA в MVP).
- **PWA** — временный интерфейс для iOS.

### 8. Синхронизация

- **ApprovalStore** — постоянно, gRPC.
- **Память** — on-demand, gRPC.
- **Файлы** — Syncthing.
- **Конфликты** — LWW + векторные часы.

### 9. Безопасность

- **ApprovalStore** — все действия через одобрение.
- **Белый список приложений** — настраиваемый.
- **Аудит** — все действия логируются.
- **Локальное хранилище** — данные не уходят в облако.
- **Tailscale** — защищённая сеть между устройствами.

### 10. Плавающий виджет

- **Две зоны:** «Т» (действие) и «...» (меню).
- **Адаптивный:** голос ↔ текст.
- **Overlay на Android**, отдельное окно на ПК.
- **Голосовой ввод** с редактированием текста.
- **Всегда под рукой.**

### 11. Иерархическая память

- **Core memory** — всегда в контексте (персона, владелец, задачи, предпочтения).
- **Recall memory** — история разговоров.
- **Archival memory** — документы, факты.
- **Агент сам управляет** памятью через tool calls.
- **Персонализация** — секретарь знает владельца.

## Как работает

### Сценарий 1: Поиск документа

**Пользователь:** «Найди смету за апрель».

**Tensa:**
1. Голос → текст (Whisper).
2. Текст → LLM (Gemma 4 E2B).
3. LLM → JSON: search_files.
4. Поиск в Lance.
5. Результат: список файлов.
6. Пользователь открывает.

### Сценарий 2: Отправка письма

**Пользователь:** «Отправь Ивану смету за апрель».

**Tensa:**
1. Голос → текст.
2. LLM → JSON: search_files + send_email.
3. Поиск файла.
4. Создание действия в ApprovalStore.
5. Уведомление владельцу (Telegram / виджет).
6. Владелец одобряет.
7. Отправка письма.

### Сценарий 3: Встреча

**Пользователь:** «Назначь встречу с Петром на завтра в 15:00».

**Tensa:**
1. Голос → текст.
2. LLM → JSON: check_calendar + create_calendar_event.
3. Проверка календаря.
4. Если свободно — создание события.
5. Если занято — предложение альтернатив.
6. Создание действия в ApprovalStore.
7. Владелец одобряет.

### Сценарий 4: Персонализация

**Пользователь:** «Зови меня Шеф».

**Tensa:**
1. Голос → текст.
2. LLM → JSON: core_memory_append.
3. Обновление блока human в core memory.
4. Секретарь теперь обращается «Шеф».

## Философия

### 1. Приватность — фундамент

Данные пользователя — его данные. Не облако, не корпорация, не
третьи лица. Локальные модели, локальное хранилище, Tailscale.

### 2. Контроль — обязателен

Секретарь не должен делать ничего без одобрения. ApprovalStore —
центральный элемент. Пользователь решает, что делать.

### 3. Кроссплатформенность — свобода

Не привязывать пользователя к экосистеме. Windows, Linux, Android,
macOS, iOS — работают вместе.

### 4. Открытость — доверие

Open-source (текущий этап). Пользователь может проверить, что
делает Tensa. Нет «чёрных ящиков».

### 5. Простота — для пользователя

Сложность — внутри. Снаружи — простой виджет, голосовой ввод,
понятные команды.

### 6. Память — персонализация

Секретарь помнит владельца, адаптируется, учится. Это не «чат-бот»,
это настоящий секретарь.
