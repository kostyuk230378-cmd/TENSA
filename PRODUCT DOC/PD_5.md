## Назначение

Этот документ описывает, как Tensa помнит владельца и как
формирует свою персону. Это ключевое отличие от обычных ассистентов,
которые не помнят ничего между сессиями.

---

## Что такое память Tensa

Tensa — не «чат-бот», который забывает всё после закрытия. Это
**секретарь**, который:
- Помнит владельца.
- Помнит свои обязанности.
- Помнит разговоры.
- Помнит документы.
- Учится со временем.

Память Tensa — **иерархическая** (вдохновлено Letta / MemGPT):
- **Core memory** — всегда в контексте.
- **Recall memory** — история разговоров.
- **Archival memory** — долговременное хранилище.

---

## Core memory: персона и владелец

### Что это

Core memory — четыре блока, которые **всегда находятся в контексте
LLM**:
- persona — персона секретаря.
- human — информация о владельце.
- tasks — текущие задачи.
- preferences — предпочтения владельца.

Эти блоки **редактируются агентом** через инструменты
(core_memory_replace, core_memory_append).

### Пример: персона

**persona:**
```
Я — Tensa, персональный ИИ-секретарь. Моя задача — помогать
владельцу управлять документами, почтой, календарём, Telegram и
приложениями. Я работаю на русском и английском языках. Я не
выполняю действия без одобрения владельца. Я уважаю приватность и
не передаю данные третьим лицам.
```

### Пример: владелец

**human:**
```
Владельца зовут Александр. Он предпочитает обращение «Шеф».
Его язык: ru. Часовой пояс: Europe/Moscow.
```

### Пример: задачи

**tasks:**
```
Активные задачи:
- Подготовить смету за апрель.
- Отправить договор Ивану.
```

### Пример: предпочтения

**preferences:**
```
Владелец предпочитает:
- Краткие ответы.
- Деловой стиль.
- Без эмодзи.
```

---

## Персона секретаря

### Как формируется

При первом запуске Tensa **спрашивает владельца**:
- Как вас зовут?
- Как к вам обращаться?
- Как называть вашего секретаря?
- Ваш часовой пояс?

На основе ответов создаётся персона.

### Как меняется

Персона **меняется со временем**:
- Владелец говорит «зови меня Шеф» → core_memory_replace.
- Владелец говорит «предпочитаю краткие ответы» → core_memory_append.
- Владелец ставит новую задачу → core_memory_append.

### Что это даёт

- **Персонализация** — секретарь знает, как обращаться.
- **Контекст** — секретарь помнит предпочтения.
- **Адаптация** — секретарь меняется под владельца.

---

## Recall memory: история разговоров

### Что это

Recall memory — **полная история разговоров** с владельцем.
Не всегда в контексте — извлекается по запросу.

### Как работает

- Каждое сообщение сохраняется.
- Поиск по истории (FTS5).
- Агент может искать через recall_memory_search.

### Когда используется

- Владелец спрашивает о прошлом разговоре.
- Нужно вспомнить контекст.
- Нужно найти ранее сказанное.

### Пример

**Пользователь:** «Что мы обсуждали вчера?»

**Tensa:**
```json
{
  "action": "recall_memory_search",
  "params": { "query": "вчера", "limit": 10 },
  "reasoning": "Поиск в истории разговоров"
}
```

---

## Archival memory: долговременное хранилище

### Что это

Archival memory — **документы, факты, важная информация**.
Не всегда в контексте — извлекается по запросу.

### Что хранится

- Документы (PDF, DOCX, XLSX, PPTX).
- Факты о владельце.
- Информация о контактах.
- Полезные детали.

### Как работает

- Векторный поиск (Lance).
- Эмбеддинги (multilingual-e5-small).
- Агент может искать через archival_memory_search.
- Агент может добавлять через archival_memory_insert.

### Пример

**Пользователь:** «Иван предпочитает получать сметы в PDF».

**Tensa:**
```json
{
  "action": "archival_memory_insert",
  "params": {
    "content": "Иван предпочитает получать сметы в PDF",
    "tags": ["иван", "предпочтения", "почта"]
  },
  "reasoning": "Сохранение важного факта о контакте"
}
```

## Как это отличается от других

### От Siri / Google Assistant / Alexa

| Критерий | Siri / Google / Alexa | Tensa |
|---|---|---|
| Персона | Фиксированная | Настраиваемая |
| Имя владельца | Не помнит | Помнит |
| Предпочтения | Не помнит | Помнит |
| История | Ограниченная | Полная |
| Документы | Нет доступа | Полный доступ |
| Приватность | Облако | Локально |

### От Notion AI / ChatGPT

| Критерий | Notion AI / ChatGPT | Tensa |
|---|---|---|
| Персона | Фиксированная | Настраиваемая |
| Память | Сессия | Иерархическая |
| Локальные файлы | Нет доступа | Полный доступ |
| Приватность | Облако | Локально |
| Контроль | Нет | ApprovalStore |

### От Obsidian / Logseq

| Критерий | Obsidian / Logseq | Tensa |
|---|---|---|
| Персона | Нет | Настраиваемая |
| ИИ | Нет (или плагины) | Полный |
| Память | Файлы | Иерархическая |
| Действия | Нет | Реальные |

## Преимущества

### 1. Персонализация

Секретарь знает, как обращаться к владельцу, какие у него
предпочтения, какие задачи.

### 2. Контекст

Секретарь помнит разговоры, документы, контакты.

### 3. Адаптация

Секретарь меняется со временем, учится.

### 4. Приватность

Вся память — локально. Нет облака Tensa.

### 5. Контроль

Владелец видит, что помнит секретарь. Может редактировать.

---

## Управление памятью

### Что может владелец

- **Просматривать** core memory (persona, human, tasks, preferences).
- **Редактировать** core memory вручную.
- **Искать** в recall memory.
- **Искать** в archival memory.
- **Удалять** записи.
- **Экспортировать** память.
- **Импортировать** память.

### Что может агент

- **Читать** core memory (всегда).
- **Редактировать** core memory (через tool calls).
- **Искать** в recall memory.
- **Искать** в archival memory.
- **Добавлять** в archival memory.

### Что НЕ может никто

- **Удалять** core memory блоки (только заменять).
- **Читать** секреты (они не в памяти).
- **Передавать** память третьим лицам.

---

## Безопасность

### Что НЕ хранится в памяти

- Пароли.
- Токены.
- Ключи.
- Секреты.

### Что хранится

- Имя владельца.
- Предпочтения.
- Задачи.
- Документы.
- Разговоры.
- Факты.

### Защита

- Локальное хранилище.
- Шифрование at rest (v0.2+).
- Remote wipe (v0.2+).
- Аудит изменений.

## Примеры использования

### Пример 1: Знакомство

**Первый запуск:**

**Tensa:** «Как вас зовут?»
**Владелец:** «Александр».
**Tensa:** «Как к вам обращаться?»
**Владелец:** «Шеф».
**Tensa:** «Как называть вашего секретаря?»
**Владелец:** «Tensa».
**Tensa:** «Ваш часовой пояс?»
**Владелец:** «Europe/Moscow».

**Результат:**
- persona: «Я — Tensa...»
- human: «Владельца зовут Александр. Он предпочитает обращение «Шеф»...»

### Пример 2: Предпочтения

**Владелец:** «Предпочитаю краткие ответы».

**Tensa:**
```json
{
  "action": "core_memory_append",
  "params": {
    "block": "preferences",
    "value": "\nВладелец предпочитает краткие ответы."
  },
  "reasoning": "Обновление предпочтений владельца"
}
```

**Результат:** preferences обновлён.

### Пример 3: Поиск в истории

**Владелец:** «Что мы обсуждали вчера?»

**Tensa:**
```json
{
  "action": "recall_memory_search",
  "params": { "query": "вчера", "limit": 10 },
  "reasoning": "Поиск в истории разговоров"
}
```

**Результат:** список сообщений за вчера.

### Пример 4: Добавление факта

**Владелец:** «Иван предпочитает получать сметы в PDF».

**Tensa:**
```json
{
  "action": "archival_memory_insert",
  "params": {
    "content": "Иван предпочитает получать сметы в PDF",
    "tags": ["иван", "предпочтения", "почта"]
  },
  "reasoning": "Сохранение важного факта о контакте"
}
```

**Результат:** факт в архиве.

### Пример 5: Обновление персоны

**Владелец:** «Теперь зови меня Александр».

**Tensa:**
```json
{
  "action": "core_memory_replace",
  "params": {
    "block": "human",
    "value": "Владельца зовут Александр. Он предпочитает обращение «Александр». Его язык: ru. Часовой пояс: Europe/Moscow."
  },
  "reasoning": "Обновление обращения к владельцу"
}
```

**Результат:** human обновлён.
